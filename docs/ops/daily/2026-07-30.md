固定した契約（回帰したら落ちるもの）:

- **URL 正規化の集約**: 8 通りの入力（`x.com` / `twitter.com` / `www.` / `m.` / `mobile.` / `/i/web/status/` / `/i/status/` / intent の `tweet_id`）が
  全て単一の `https://x.com/i/status/<id>` に畳まれること。`http→https` 昇格・空白 trim・`?s=20` 等の除去・`#` 除去も含む。
- **失敗分類の区別**: `X_PROFILE_URL_NOT_SUPPORTED`（プロフィール/ホーム）と `INVALID_X_STATUS_URL`（不正な status）と
  `UNSUPPORTED_HOST` は**利用者に返すメッセージが違う**ので、取り違えを検知できるようにした。
- **ホスト詐称の拒否**: `x.com.evil.test` / `tiktok.com.evil.test` が canonical として通らないこと（前方一致でなく集合一致であることの固定）。
- **短縮リンクの素通し**: `t.co` / `vt.tiktok.com` / `vm.tiktok.com` は正規化せず（=ネットワーク解決が別途要る）、
  ただしクエリだけは落とすこと。
- **鮮度判定の「不明＝期限切れ」原則**: `expiresAt` が **欠落**・**パース不能**な場合に `true`（＝再取得）を返すこと。
  ここが逆転すると利用者に死んだ署名付き URL を返すため、テストに意図をコメントで残した。
  併せて 2 分の stale-soon 窓の内外・**複数 media のうち 1 件でも stale なら再取得**・
  未完了ジョブ/空 media では発火しない・**他プラットフォームのジョブには反応しない**ことを固定。
