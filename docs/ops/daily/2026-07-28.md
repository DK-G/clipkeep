## 2. 実装

### 追加: `scripts/loop-health-check.mjs` ＋ `npm run check:loop`

散文のチェックリストではなく**1コマンド**にした。理由は、今回の 2 件の事故がどちらも
「見れば分かる情報を誰も見なかった」型であり、**人（エージェント）の記憶に依存する手順は同じ形で再発する**ため。

検査 4 項目・**BLOCKER があれば exit 1**（無人実行が黙って先に進めない）:

| # | 検査 | 判定 | 落ちたときの意味 |
|---|---|---|---|
| 1 | `wrangler whoami`（ローカル `node_modules/wrangler/bin/wrangler.js` を直接起動＝shell 非経由） | BLOCKER | 何を実装しても本番に届かない |
| 2 | `/api/v1/health` == 200 | BLOCKER | 本番停止 |
| 3 | `/sitemap.xml` == 200 かつ `<loc>` >= 100 | BLOCKER | 発見が源流で壊れた（`?locale=` 一掃後の定常は 509） |
| 4 | `/api/v1/platform-status` の per-PF `status` / `uptimePct` | WARN | 抽出上流の障害進行中 |

設計上の判断:

- **`uptimePct < 90` も劣化として拾う**（最新プローブが緑でも拾う）。twitter は `status=limited` で
  自明だったが、「直近1回は 200 だが30日で 60%」という形の劣化は最新値だけ見ると消える。
- **wrangler の検出は exit code だけに頼らない**。実測で `whoami` は未ログインでも `Not logged in.` を
  出しつつ exit 0 を返しうるため、**出力文字列（`not logged in` / `CLOUDFLARE_API_TOKEN`）も併せて判定**する。
- **`npx` を使わず `process.execPath` で直接起動**。Windows で `npx.cmd` を `shell:false` で spawn すると
  Node の EINVAL に当たり、`shell:true` は不要なシェル経由を増やすため。既存 `run-growth-review.mjs` と同じ流儀。
- **PowerShell 非依存**（既存の `check:*` は `.ps1`）。健全性チェックは最も止まってはいけない層なので、
  実行環境の前提を1つ減らした（HC-7 の `ignoreBinaries: ["powershell"]` 議論とも整合）。
- 出力末尾に **daily log へそのまま貼れる markdown 表**を吐く（記録の手間＝省略の動機を消す）。
